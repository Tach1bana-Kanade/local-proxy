## 1. 产品目标与完成边界

目标是让用户无需判断网站是否“海外”，在常用网站间切换时自动使用合适的网络。界面使用“直连”“代理”“未知”，不把网站国籍、IP 地域和网络可达性混为一谈。

保留 SwiftUI + 本机 PAC 服务 + Quickcat 架构。PAC 对每个域名执行本地匹配，不调用在线分类 API，不进行测速。智能模式确认后，规则库中的网站自动参与分流，无需逐条确认。

网站分流只作用于遵循本工具 PAC 的应用。主域名与网页资源域名分别匹配，不能保证只设置一个域名就覆盖网站全部图片、登录和 API 请求。第一版不自动抓取并添加关联域名。

必须交付完整闭环：启用智能分流 → 自动匹配 → 自动更新 → 未知域名诊断 → 手动覆盖 → 退出/停用恢复。只增加一个开关或几个硬编码域名不算完成。

## 3. 模式、确认与生命周期

### 3.1 模式定义

内部用清晰的三种模式，避免两个互相矛盾的开关：

| 模式 | 网络行为 |
| --- | --- |
| off | 停止本工具的网站分流并恢复原 PAC；保留配置 |
| manual | 仅启用手动规则；其余直连，兼容旧网站白名单 |
| smart | 手动规则优先，其次规则库，未知直连 |

主界面突出“智能分流”开关。关闭该开关进入 off 并恢复原 PAC；“仅手动规则”放在模式选择或高级设置中。关闭网站分流不结束已启动 App 的固定全应用代理进程；UI 说明两者作用范围。

### 3.2 一次确认

第一次启用 smart 时显示一张确认卡，文案必须清楚包含：

> 开启后，工具将根据域名规则自动选择直连或 Quickcat 代理。未收录网站默认直连，你的手动规则优先。规则库会定期更新，后续更新自动应用。此功能只影响遵循本工具自动代理配置的应用。

提供“确定并开启”和“取消”。取消不得写系统 PAC 或改变当前模式。确认记录本地持久保存，同一规则来源、相同模式下再次开启以及正常规则更新不再确认。不新增其他来源、不默默改变未知域名策略。

启用前要求：可用的非空规则快照、Quickcat HTTP 21081 端口可连接、PAC 服务自检成功、没有待处理恢复冲突。端口可用只代表本机代理入口可连接，不标为已验证互联网畅通。

启用失败不显示“已开启”，保留原工作模式及原设置；回滚失败显示“需要恢复”。smart 模式不能再要求“至少存在一个手动代理网站”。

### 3.3 启动、退出与故障

- 不新增开机自启动或后台守护进程。正常退出恢复原 PAC；下次启动记住用户偏好但不静默改系统设置，点击开关恢复使用，不重复首次产品确认。
- 异常退出有恢复快照时，先执行现有恢复流程；恢复前禁止重新应用配置。外部修改 PAC 时不得自动覆盖。
- 运行中 Quickcat 不可用时，保留代理规则并显示错误；不得把整个模式悄悄降级为直连。
- `off` 时允许更新规则库和编辑规则，但不得修改系统 PAC；显示“已保存，开启分流后生效”。

## 4. 确定性的路由规则

匹配顺序固定如下，Swift 解释结果与生成的 PAC 必须一致：

1. 本地目标保护：localhost、单标签主机名、`.local`、`.lan`、字面量回环/私网/链路本地地址等保持直连。
2. 已启用手动规则：先比较匹配域名标签的具体程度；同一域名 exact 优先于 suffix。
3. smart 模式下的规则库：同样按域名具体程度、exact 优先的顺序选择；完全同级的直连/代理冲突固定选择直连，并计入规则库冲突统计。
4. 未命中返回 DIRECT。

手动规则整体优先于规则库，即使规则库条目更具体。系统本地目标保护是手动规则优先的例外，界面不允许将这些目标设为代理。

`exact` 只匹配该主机名；`suffix` 匹配该域名及其子域名，必须有点分隔边界。`example.com` 不匹配 `notexample.com`。默认新手动规则使用 suffix，界面明确“包含子域名”；也支持 exact。不得自动去掉 `www` 或归并为最后两段域名，避免共享托管与公共后缀误归并。

已停用的手动规则不参与匹配，后续可命中自动规则。界面提示“停用后恢复自动判断”；想强制直连必须设置 action=direct。同一 domain+match 只保留一条手动记录，用户修改即更新，不以数组偶然顺序解决冲突。

代理只返回 `PROXY 127.0.0.1:21081`，不能追加 `; DIRECT`。PAC 正常执行时该规则不静默回退；不能把它宣传为全系统防泄漏，因为客户端仍可能忽略 PAC。

PAC 不为判定普通公网域名地域而调用 DNS。字面量 IPv4/IPv6 与本地域名用纯匹配保护；若企业域名解析到私网，允许用户添加显式直连。不能声称无 DNS 查询即可识别所有私网解析目标。

## 5. 规则库：离线可用、自动更新、失败可恢复

### 5.1 固定数据来源

首版使用 Loyalsoldier/v2ray-rules-dat 的 `direct-list.txt` 与 `proxy-list.txt`。不引入广告拦截列表，不添加在线 AI 或 GeoIP 分类接口。

数据入口：

- `https://raw.githubusercontent.com/Loyalsoldier/v2ray-rules-dat/release/direct-list.txt`
- `https://raw.githubusercontent.com/Loyalsoldier/v2ray-rules-dat/release/proxy-list.txt`

以上是来源入口；一次更新应先解析 release 分支的同一个提交版本，再从该固定提交读取两份文件，避免下载途中上游更新导致混用两个版本。版本解析失败时保留旧快照。请求无须用户 GitHub Token，限流作为可恢复失败处理。

实现前读取上游真实格式、许可和归属要求；随包快照保留来源、上游版本、下载时间、SHA-256、许可文本和条目统计。不凭记忆擅自给第三方数据换许可证。不得用虚构域名列表冒充正式数据。

解析至少支持裸域名后缀、`domain:` 后缀和 `full:` 精确语义（按实际来源格式确认）；空行、注释可忽略。`regexp:`、关键词等未支持语义必须单独计数，并在诊断详情标为未支持，不可误解析为普通域名或直接执行远程代码。畸形条目视为更新失败。

默认单文件上限 20 MiB、单行上限 4096 字节、两份合计上限 500,000 个解析条目；允许按实测调整并说明原因。两份文件均须有有效条目，必须完成标准化、去重与冲突处理后才能发布。来源完整性校验不等于独立签名认证，不做错误的安全承诺。

### 5.2 首次启动与缓存

- 应用随包包含一个经验证的真实快照；断网且本机无缓存也可分类。确保 SwiftPM 资源能进入打包后的 `.app`，不能只在仓库运行时可读。
- 读取优先级：最近有效的本地缓存 → 随包快照。缓存损坏保留原文件用于诊断，回退随包资源并显示原因，不当作空规则成功运行。
- 若缓存与随包快照都不可用，smart 禁用并展示修复入口，manual 仍可工作。

### 5.3 定期更新

- 默认开启自动更新：App 启动时若距上次成功检查超过 24 小时则检查；App 运行期间每 24 小时检查；提供“立即更新”和自动更新开关。
- 不创建 launchd、系统定时任务或 Codex 自动化。App 未运行时不更新。
- 失败保留当前快照，按 15 分钟、1 小时、6 小时退避重试，且同一时刻仅允许一个更新任务；成功后恢复正常周期。手动更新可提前重试。
- 先尝试明确直连下载；失败且 Quickcat 可用时显式通过 Quickcat 重试，不能依赖当前系统 PAC，避免更新路径循环。网络请求有超时和取消，UI 不阻塞。
- 下载与解析写入候选快照，验证完成后原子发布。保留一个上一有效版本，提供“回退上一版本”；回退后暂停自动更新，用户重新启用时再恢复。
- 更新只替换自动规则，不覆盖手动规则、用户确认记录和模式。更新不弹逐站确认，状态栏展示成功或失败。
- UI 显示：来源、当前版本、更新时间、直连/代理数量、未支持/冲突数量、最近更新错误。

## 6. 未知网站诊断与确认

提供“检查网站”输入框。用户粘贴域名或 HTTP/HTTPS URL 后点击检查，先显示当前规则命中情况，再按需检测，结果出现前不写规则。

显示字段：规范化域名、当前路由、匹配来源/理由、直连结果、代理结果和建议。未知域名在正常浏览中仍按 DIRECT，不后台自动扫描或探测所有访问。

### 6.1 探测要求

- 探测不携带原 URL 的路径、查询参数、Cookie、认证头或用户会话；只访问 `https://规范域名/`，不能因输入 http 就发送原业务请求。
- 两个独立临时客户端：一个明确禁用环境/系统代理/PAC，一个明确通过 Quickcat HTTP 21081。需要用测试证明两个通道不同，不能只给 UI 换标签。
- 总预算默认 8 秒，每条通道最多 2 次尝试；并发执行、可取消，实际网络操作也必须停止。DNS 阻塞不能无限拖延整个任务。
- 优先 HEAD；不支持时可进行有响应大小上限的小 GET，最多读取 16 KiB 后停止。保留正常 TLS 证书验证。
- 不自动跟随重定向；记录状态码和“目标发生跳转”，不携带跳转地址继续扫描。
- 对直接输入的本地/保留目标不探测；直连探测对解析到的本地/保留地址也拒绝，并处理解析校验与实际连接之间的一致性。不要提供任意内网探测入口。
- 手动强制代理的网站不自动执行直连探测，显示“按现有代理规则跳过直连测试”。
- 403、429、证书错误、登录挑战与代理端口开放都不能单独推断“需要代理”或“网站可正常使用”。

### 6.2 结果规则

| 观察结果 | 界面建议 |
| --- | --- |
| 直连正常，代理也正常或失败 | 建议直连；不因单次速度差自动切换 |
| 直连重复连接失败，代理获得正常 HTTPS 响应 | 建议代理，解释两条路径差异 |
| 两条路径都失败，或存在证书/限流/访问限制导致无法判断 | 暂无法判断，显示具体失败阶段 |
| 返回重定向 | 只说明原主机可响应，不保证目标站点或页面可用 |
| Quickcat 不可用 | 代理检测不可用，仍可显示直连结果 |

用户可点击“确认使用代理”或“确认直连”，也可关闭结果。保存为手动规则，立即参与后续分流；网络分流关闭时仅保存并提示。不得因检测成功直接修改规则。

探测缓存仅在内存保存 10 分钟，键包含域名与网络代次；网络路径变化后失效。输入变化或关闭面板取消旧请求，旧结果不得覆盖新域名；单域名合并并发检测。手动确认不会因缓存到期失效。

## 7. 手动规则、迁移与持久化

采用带 `schemaVersion` 的新配置；至少包含模式偏好、首次确认版本、自动更新设置及手动规则。运行时 activeMode 与保存的偏好分开，不能启动即谎报已启用。

手动规则至少记录：`id`、`domain`、`match`（exact/suffix）、`action`（direct/proxy）、`enabled`、创建/修改时间、来源（用户编辑/诊断确认/旧数据迁移），可附诊断理由。不把探测时间当永久规则有效期。

迁移现有 `websites.json`：

- enabled=true → 同 ID、同域名、suffix、proxy、enabled=true。
- enabled=false → 保持 disabled，不转为显式直连。
- 旧用户不自动开启 smart，不自动让规则库接管现有白名单。
- 先校验并完整写入新文件，成功后才以新配置运行；保留旧文件作为迁移备份，不删除、不重复导入。
- 新格式文件已存在但损坏时，显示恢复错误，不静默覆盖为默认空列表；迁移应幂等，失败可重试。

沿用 `~/Library/Application Support/Proxy Apps/`，目录 0700、配置文件 0600、原子写入。新增持久状态尽量集中，不让多份独立 JSON 出现半提交。具体 JSON 字段、日期编码和恢复策略写入开发文档并测试。

添加/编辑/停用/删除规则时先构建候选配置和 PAC，持久化或应用失败可回滚。UI 只在事务成功后显示成功。删除规则是删除该条记录，不批量清理文件或目录。

## 8. PAC 编译、发布与恢复

- 执行路径：本地保护 → 手动规则 → smart 的自动规则 → DIRECT。manual 完全跳过规则库。
- 预编译规则索引和 PAC 文本，按标签逐层查找或使用等价高效索引；禁止每次请求线性扫描全部自动域名。
- 使用浏览器普遍支持的 PAC JavaScript 语法，域名通过 JSON 安全编码，不拼接可执行远程表达式。编译顺序稳定、结果可复现。
- `PACContentStore` 保存已编译不可变快照；不要在每次 GET 或长时间持锁时重新编译大规则库。
- 配置成功变化后发布带 revision 的 PAC URL，例如 `/proxy.pac?v=<revision>`；同时修改服务器路径/query 解析、缓存响应、系统 PAC 更新和恢复记录。现有服务器只认精确 `/proxy.pac`，不能仅改 URL 字符串。
- 第一次接管前保存真正的原系统状态；后续 revision 更新不得把自己的旧 PAC 当成“原状态”。为切换中的旧/新 URL 记录明确归属，崩溃在中间步骤也能恢复，不能仅凭 URL 有 localhost 就认定可以覆盖。
- 原始恢复快照、发布日志和当前活动配置要有可恢复的提交顺序；部分服务写失败回滚已修改服务。回滚失败留快照并阻止继续启用。
- 仅监听 `127.0.0.1`。保留端口冲突处理，对读写超时、断开客户端、请求大小和 send 失败提供界限，不能一个异常请求卡死服务。
- PAC revision 会促使客户端重新获取配置，但不能保证现有长连接立即改路。UI 使用“配置已更新，必要时重新加载页面”，实际行为需分别验证 Safari 和 Chrome。

## 9. App 启动方式兼容

保留已有普通启动与全应用代理能力，并增加 Chromium 应用的“按网站规则启动”：

| 启动方式 | 必须行为 |
| --- | --- |
| 普通启动 | 不新增代理环境/参数；仍可能遵循当前系统 PAC，不得标为强制直连 |
| 全部代理启动 | 保留原固定代理和环境变量能力，明确标注其不按网站规则分流 |
| 按网站规则启动 | 使用当前有效 PAC；不得同时注入固定 `--proxy-server` 或全流量代理环境变量 |

按网站规则启动要求分流已启用且 PAC 服务健康。目标已运行则提示先完全退出，不杀进程。非 Chromium 应用只展示已验证可支持的能力，不假装所有 App 都支持 PAC 参数。

用固定 PAC URL 参数启动的 Chromium 进程不保证跟随后续系统 PAC URL 变化：发布新 revision 后应提示该模式启动的应用可能需要重启，不能宣称缓存必然即时刷新。优先验证系统 PAC 路径和真实启动参数的差异并写清使用限制。

## 10. UI 与错误处理

主界面采用现有 SwiftUI 风格，中文文案，至少包含：

1. 智能分流主卡：开关、当前模式、实际运行状态、首次确认。
2. 规则库卡：来源/版本/数量/更新状态、“立即更新”、自动更新开关、可用时的版本回退。
3. 网站检查卡：输入、异步状态、命中原因、双路结果、确认直连/代理。
4. 手动规则卡：搜索、直连/代理筛选、范围、启用状态、编辑/删除。
5. 网络恢复与 Quickcat 状态：复用现有错误入口，避免显示成功但网络未配置。

分析、下载、编译在后台完成。更新规则库时仍可查看现有规则和当前模式；需要修改活动配置的操作串行化，防止更新覆盖用户刚保存的规则。不用一个全局 busy 锁把整个界面长时间锁死。

错误区分“下载失败但继续用旧规则”“配置未应用”“代理入口不可用”“需要恢复”。不在日志记录用户完整 URL 或探测响应正文。
